# Полный прогон на RTX A6000

Пакет предназначен для самостоятельного запуска на арендованном Linux-сервере.
Удалённое подключение не требуется. Изменения находятся в локальной ветке
`feature/advanced-phase-reconstruction`.

RTX A6000 имеет 48 ГБ памяти: [характеристики NVIDIA](https://www.nvidia.com/en-us/products/workstations/rtx-a6000/).
Программа подбирает батч по измеренной производительности и оставляет память для
оптимизатора, валидации и физических учителей. Заполнение всей VRAM само по себе
не является целью.

## Быстрый запуск

Локально собрать переносимый архив:

```powershell
.venv\Scripts\python.exe tools/build_training_bundle.py
```

Получится `results/photonika-a6000.tar.gz`. В нём актуальные исходники, тесты,
инструкции и скрипты. Веса, личные файлы, Git и обучающие изображения не входят.
Файлы проверяются по SHA256 в `MANIFEST.json`. Архив использует актуальный пакет
`ml/`; старую папку `remote_upload/` копировать не нужно.

На сервере нужен готовый CUDA PyTorch (рекомендуется PyTorch 2.4+), Python 3.10+
и шрифты DejaVu или Liberation. Используйте CUDA-окружение провайдера. После
переноса архива выполните:

```bash
tar -xzf photonika-a6000.tar.gz
cd photonika-a6000
bash scripts/train-a6000.sh --install --minutes 180
```

`--install` устанавливает зависимости проекта, сохраняя предоставленный CUDA
PyTorch. При готовых зависимостях этот флаг можно опустить. Проверка CUDA
происходит перед установкой. При необходимости укажите Python через переменную
`PHOTONIKA_PYTHON`.

Посмотреть план без GPU, установки зависимостей и скачивания:

```bash
bash scripts/train-a6000.sh --dry-run --minutes 180
```

`--minutes` задаёт целевой бюджет текущего запуска. По умолчанию это 3 часа, а не
неограниченное использование аренды. Подготовка данных, проверки и финализация
могут потребовать дополнительного времени; оставляйте запас до окончания аренды.
Установка зависимостей выполняется до начала отсчёта этого бюджета.

## Что выполняется

1. Проверяются GPU и BF16. Загружаются 100 фотографий DIV2K HR, если не указан
   `--skip-fetch`. Для своих фотографий используйте `data/photos/` и этот флаг.
2. Изображения разделяются по хешу содержимого на train/val/test. Дубликаты и
   копии зарезервированных классических фото исключаются. Минимум — 32 исходника
   train и по 4 val/test. Это рабочий минимум, не доказательство обобщения.
3. Создаётся mmap-пул 50 000 изображений 128×128. Он не загружается целиком в RAM.
4. Сравниваются три V2-кандидата: `base32 / 4 стадии / stage16` (7,79 млн параметров),
   `base48 / 8 стадий / stage24` (23,34 млн) и `base64 / 8 стадий / stage32` (41,34 млн).
   При бюджете 3 часа на каждый пилот отводится до 15 минут.
5. Архитектура выбирается по PCC + SSIM на validation после 8-битного квантования
   ДОЭ. Оставшееся время используется для обучения победителя. Большая сеть не
   получает приоритета перед меньшей.
6. Итоговые и пилотные веса повторно сравниваются только на validation. Лучший
   checkpoint экспортируется в `data/weights/doe_a6000.pt`.
7. После фиксации выбора проводится test: 16 четвёрок каждой категории и
   классические наборы; сравниваются сеть, сеть + GS-25, GS-100 и GS-100 + Adam-200.
   Seed 0/1/2 меняет случайные старты базовых методов; выход обученной сети
   детерминирован. Время измеряется после прогрева.

Подготовка, подбор батча и промежуточные проверки вычитаются из доступного времени,
поэтому фактическое основное обучение может быть короче номинальных двух часов.
Отказ крупного кандидата сохраняет возможность закончить с меньшей моделью.

## Модель и обучение

V2 использует residual U-Net, Fourier-обработку и attention в нижнем уровне,
отдельные фазы четырёх изображений и обучаемые физические проекции GS. Сочетание
пространственной и Fourier-обработки исследуется, например, в
[SFO-solver, Nature Communications, 2025](https://www.nature.com/articles/s41467-025-62997-z).
Реализация здесь адаптирована под фиксированные четыре плоскости и заданную
одно-FFT формулу Френеля; это самостоятельный экспериментальный вариант.
Метрики статьи к нашей задаче не переносятся.

Обучение включает BF16 для свёрток и линейных слоёв, float32/complex64 для фаз,
FFT и метрик, activation checkpointing, deep supervision промежуточных стадий,
straight-through квантование фазы в 256 кодов, EMA весов и периодические
GS/Adam-подсказки от физического оптимизатора. Distillation учитывает, что общая
фаза не меняет амплитуду. Есть накопление градиентов (`--grad-accum`).

Пул по умолчанию требует около 0,8 ГБ на диске; фото, архив данных и несколько
checkpoint требуют ещё несколько гигабайт. Рекомендуется минимум 12 ГБ свободного
места. Классические тестовые изображения не восстанавливаются в ходе пилотов:
preview отключён до финальной проверки.

## Логи, остановка и продолжение

```bash
tail -f data/runs/a6000/quality_b48_u8/training.log
cat data/runs/a6000/manifest.json
touch data/runs/a6000/STOP
```

После мягкой остановки удалите только созданный флаг и продолжите:

```bash
rm data/runs/a6000/STOP
bash scripts/train-a6000.sh --resume --skip-fetch --minutes 180
```

Новый бюджет добавляется к незавершённому прогону. Проверяются хеши исходников,
источников фото, настроек и весов. Завершённые пилоты не повторяются; незавершённое
обучение восстанавливает Adam, EMA, RNG и прогресс расписания. Завершённый
эксперимент при `--resume` возвращает сохранённый результат. Для нового эксперимента
укажите новые `--output` и `--weights`; прежние файлы не перезаписываются.

Результаты:

- `data/weights/doe_a6000.pt` — выбранные веса.
- `data/runs/a6000/test_benchmark.json` — итоговый test и базовые методы.
- `data/runs/a6000/selection_validation.json` — основание выбора checkpoint.
- `data/runs/a6000/photo_sources.json` — исходники фото и разбиение.
- `data/runs/a6000/*/last.pt` — состояние для продолжения обучения.

Для синтеза:

```bash
python3 -m ml.cli synth --weights data/weights/doe_a6000.pt --method net --inputs 1.png 2.png 3.png 4.png --out results/a6000_synthesis
python3 tools/verify_submission.py --doe results/a6000_synthesis/doe.png --inputs 1.png 2.png 3.png 4.png
```

Пакет и локальные проверки не подтверждают превосходство над GS. Такой вывод
возможен после реального обучения и сравнения итогового отчёта. Существующие
веса сервера по умолчанию автоматически не заменяются.

Локально 7 ноября 2026 прошли 171 тест; один POSIX-тест оболочки пропущен в Windows,
при этом сам Bash-скрипт отдельно проверен через Git Bash. Модель 41,34 млн
параметров выполнила BF16 forward/backward и шаг Adam с checkpointing,
квантованием и deep supervision на RTX 3050. Дополнительно проверены полный
тренер с EMA, физическим учителем, подбором батча и накоплением градиентов,
resume и benchmark с отдельными источниками фото. Это проверки работоспособности;
обучение на арендованной A6000 с нашей стороны не запускалось.

DIV2K предоставляется для академических исследований; описание и публикация
датасета: [официальная страница DIV2K](https://data.vision.ee.ethz.ch/cvl/DIV2K/).

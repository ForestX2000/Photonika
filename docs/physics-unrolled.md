# Модель с обучаемыми шагами физического восстановления

Этот документ описывает исходный вариант V1 и его короткий проверочный прогон.
Для RTX A6000 подготовлен [полный цикл с V2-моделями и переносимым пакетом](a6000.md).

`physics-unrolled` — новая архитектура для задачи «четыре амплитудных изображения
128×128 → один фазовый ДОЭ». Это кандидат для обучения и сравнения, а не заявление
о рекордном качестве. Его преимущество над GS или прежней сетью определяется
результатами на одинаковых тестовых входах после квантования ДОЭ.

## Как устроена сеть

1. U-Net предсказывает отдельную поправку к фазе каждого целевого изображения.
   Attention в нижнем уровне U-Net связывает удалённые участки изображения.
2. Дифференцируемое обратное распространение Френеля объединяет поля в один ДОЭ.
3. Каждая из `--unroll` стадий выполняет физический шаг GS, обучает веса плоскостей
   и величину шага, затем добавляет ограниченную фазовую поправку небольшой U-Net.
   Признаки ошибок каждой плоскости предварительно переносятся в координаты ДОЭ.
4. Фаза оборачивается в [−π, π]. Число стадий фиксировано при создании модели.

Нулевые выходные головы, одинаковые веса плоскостей и единичный шаг обеспечивают
проверяемый старт: необученная сеть совпадает с соответствующими итерациями GS
от физической начальной фазы. Это не обещает монотонного улучшения после обучения.

Обучение использует дифференцируемую физику и сумму MSE, PCC и локального/глобального
SSIM с дополнительным весом худших плоскостей. Отдельные эталонные фазы не нужны.
Принцип самоконтролируемого синтеза через оптическую модель описан в
[DeepCGH, Eybposh et al., 2020](https://doi.org/10.1364/OE.399624).
Архитектура в этом проекте не является воспроизведением DeepCGH.

## Обучение

Пример начального прогона для GPU с 6 ГБ памяти:

```powershell
.venv\Scripts\python.exe -m ml.training --architecture physics-unrolled --input-mode imgphase --base 16 --unroll 4 --stage-base 8 --batch 4 --lr 1e-4 --minutes 120 --output data/runs/physics_b16_u4 --weights data/weights/physics_unrolled.pt
```

Для автоматического подбора батча передайте `--batch auto`. На CUDA подбор проверяет
полный шаг с backward и выделением памяти Adam, возвращает исходные веса и RNG.
Для ограничения проверочного прогона есть `--max-steps`.

Фоновый запуск с логами и мягкой остановкой:

```powershell
.\scripts\train-local.ps1 -Architecture physics-unrolled -Base 16 -Unroll 4 -StageBase 8 -Batch 4 -Minutes 120 -RunName runs/physics_b16_u4 -WeightsName physics_unrolled.pt
.\scripts\training-status.ps1 -RunName runs/physics_b16_u4
.\scripts\stop-training.ps1 -RunName runs/physics_b16_u4
```

Для продолжения повторите ту же команду с `--resume` (или `-Resume`). Настройки
архитектуры, оптики, seed, пула и функции потерь должны совпадать. Восстанавливаются
состояние Adam, RNG и прогресс cosine scheduler; новый лимит времени продлевает
оставшуюся часть расписания. В старых checkpoint без `schedule_progress` расписание
начинается с нуля. `--init-weights` запускает отдельное обучение совместимой модели
с новым оптимизатором и расписанием.

`unet` сохраняет архитектуру исходной вещественной U-Net. `pdr` сохраняет размеры
тензоров комплексной двухмасштабной модели, исправляя каналы, батчинг, нормировку
и работу GS-стадий. Старые checkpoint без метки архитектуры распознаются по именам
тензоров. Несовместимые и неполные веса отклоняются, вместо частичной загрузки.
Старые PDR checkpoint с `unroll > 0`, фактически не содержавшие стадий, также
отклоняются: активным стадиям нужны обученные веса.

## Проверка качества и использование

```powershell
.venv\Scripts\python.exe tools/benchmark_models.py --weights data/weights/physics_unrolled.pt --device auto --count 4 --gs-iters 50 --adam-steps 100 --refine-steps 10 --out results/physics_benchmark.json
.venv\Scripts\python.exe -m ml.cli synth --inputs 1.png 2.png 3.png 4.png --weights data/weights/physics_unrolled.pt --method net --out results/physics_synthesis
.venv\Scripts\python.exe tools/verify_submission.py --doe results/physics_synthesis/doe.png --inputs 1.png 2.png 3.png 4.png
.venv\Scripts\python.exe -m pytest -q
```

Benchmark сравнивает `net`, `net+gs`, GS и GS+Adam на одинаковых входах и сохраняет PCC/SSIM
после преобразования фазы в 8-битный ДОЭ и независимого восстановления NumPy.
В отчёте есть средние результаты, худшие плоскости, отдельные категории, время
без прогрева и хеши весов/входов. Число итераций GS и доуточнения указано явно;
это разные бюджеты вычислений, поэтому качество и время следует оценивать вместе.
`--adam-steps 0` отключает GS+Adam.

Случайные val/test-наборы используют разные seed, но общие источники фотографий
с обучением. Дополнительные классические наборы (включены по умолчанию) выводятся
отдельно; `photos_classic` использует зарезервированные источники. Для утверждения
об обобщении на новые фотографии нужен более широкий отдельный датасет.

Лучшие веса и данные прогонов остаются локальными и исключены из Git. Проверочный
прогон на несколько минут подтверждает работоспособность; для выбора итоговой
модели нужны полноценное обучение, несколько seed и сравнение с сильным GS+Adam.

Локальная проверка 7 ноября 2026: модель `base=16, unroll=4, stage_base=8`, seed 42,
пул 2000, батч 4, 600 шагов AdamW, примерно 2,4 минуты на RTX 3050 6 ГБ. На 12
четвёрках test и 4 классических наборах с seed 0 средний PCC изменился с 0,4745
до 0,4945, SSIM — с 0,1199 до 0,1317. GS-50 получил PCC 0,5506 / SSIM 0,1801,
GS-50 + Adam-100 — 0,5917 / 0,2926. Этот короткий прогон подтверждает обучение,
но **не превосходство над базовыми методами**. Экспериментальные веса сохранены
отдельно в `data/weights/physics_unrolled.pt`; веса сервера по умолчанию не заменены.
Подробности локально: `results/physics_benchmark.json`,
логи и checkpoint продолжения: `data/runs/physics_unrolled_candidate/`.
